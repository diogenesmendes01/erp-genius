# Auditoria: Comercial/CRM e WhatsApp

> Auditoria somente-leitura de 2026-10-21 sobre o repositório `erp-genius` (branch `main`, commit `bc858aff`).
> Docs cruzados: 08, 09 (§Ficha, §Pipeline, §Home), 10, 26, 27, 28, 29, 30, 31, 32. Código: `src/server/comercial/`,
> `src/server/whatsapp/`, rotas `src/app/api/whatsapp/*`, telas `/pipeline`, `/leads`, `/inbox`, `/configuracao/whatsapp`,
> `prisma/schema.prisma`, `prisma/seed-whatsapp.ts`, `.env.example`. Linhas citadas refletem o código nesta data.

## Resumo

- **52 achados** na tabela: **30 CONFORME · 11 PARCIAL · 6 DIVERGENTE · 4 NAO_IMPLEMENTADO · 1 SEM_DOC.**
- A fundação do canal (bimotor, outbox, despachante, webhooks autenticados, inbox, templates, health) está implementada e **bate com os docs 26/29/30/31**; o modo simulado (`WHATSAPP_LIVE` vazio) permite testar quase todo o fluxo em UAT sem enviar mensagem real.
- A fase comercial está em **C1 + C2 implementadas, C3 (IA) não iniciada**: não existe nenhum provedor de LLM, classificação de intenção ou sugestão de CRM no código — o "IntencaoMensagem" do schema é a **outbox** de envio, não classificação por IA.
- Os **9 bloqueadores do doc 32 (B1–B9) continuam todos abertos** no código; os mais graves para o piloto são B7 (despacho não revalida etapa/ocorrência), B2 (resposta pelo celular não para a cadência) e B8 (`REAGENDAR` não pausa).
- Divergências relevantes de produto: lead em `NO_SHOW` **não aparece no Kanban** (sem coluna); pipeline B2B separado **não existe** (só flag); redistribuição de dono tem ação de servidor mas **nenhuma tela** a chama; regra dos 90 dias de posse não implementada.
